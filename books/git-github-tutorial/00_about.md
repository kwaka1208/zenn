## この本について

この本は、**Git（ギット）** と **GitHub（ギットハブ）** をはじめて使う方のためのチュートリアルです。

Gitは「ファイルの変更履歴を記録するツール」、GitHubは「その履歴をインターネット上に置いて共有するサービス」です。どちらもソフトウェア開発の現場では当たり前のように使われていますが、はじめて触るときは用語も操作も独特で、とまどう方が多いところでもあります。

そこでこの本では、**小さなメモ帳リポジトリを実際に作って育てながら**、必要なコマンドをひとつずつ覚えていきます。読むだけでなく、手元で同じ操作をしながら進めてください。

### この本で学べること

最後まで進めると、次のことができるようになります。

- 自分のパソコンでGitを使い、作業の履歴を残す
- 「あのときの状態に戻したい」を実現する
- GitHubに自分のリポジトリを公開する
- 別のパソコンに、同じリポジトリを持ってくる
- ブランチを切って作業し、あとで本流に合流させる
- プルリクエストを使って、変更をレビューしてから取り込む

### 対象読者

- Gitという言葉は聞いたことがあるが、使ったことがない方
- GUIツールで何となく使っているが、仕組みがよくわからない方
- チーム開発に参加することになり、最低限の操作を身につけたい方

プログラミングの経験は必須ではありません。ただし、次のことができると進めやすくなります。

- ターミナル（コマンドを入力する画面）を開ける
- `cd` や `ls` といったコマンドを見たことがある

:::message
ターミナルにまだ慣れていなくても大丈夫です。この本で使うコマンドは、そのつど意味を説明します。まずは書いてあるとおりに入力してみてください。
:::

## 動作環境

この本のコマンドは、次の環境を想定しています。

- macOS のターミナル
- Windows の PowerShell 7
- Linux のターミナル

Gitのコマンド（`git` で始まるもの）は、どの環境でもまったく同じです。違いが出るのは、フォルダを作る・ファイルを一覧するといった**ファイル操作のコマンド**だけです。この本では、書き方が違う箇所だけ「macOS / Linux」と「Windows（PowerShell 7）」に分けて示します。

:::message alert
Windowsに最初から入っている **Windows PowerShell 5.1** ではなく、**PowerShell 7** を使ってください。5.1はファイルに文字を書き込むときの文字コードの扱いが特殊で、この本の手順どおりに進めても結果が変わってしまうことがあります。導入方法は第2章で説明します。
:::

:::message
WSL（Windows Subsystem for Linux）やGit Bashを使う場合は、Windows向けの書き方ではなく、**macOS / Linux向けの書き方**をそのまま使ってください。
:::

## この本のコードの読み方

この本には、大きく分けて2種類のコードブロックが出てきます。

### ターミナルに入力するコマンド

```bash
git status
```

`bash` と書かれたコードブロックは、**ターミナルに入力して実行するコマンド**です。1行ずつ入力して、そのつどEnterキーを押してください。

書き方がOSで違う場合は、次のように「macOS / Linux」と「Windows（PowerShell 7）」を並べて示します。自分の環境に合うほうだけを実行してください。`powershell` と書かれたブロックは、Windows向けです。

macOS / Linux:

```bash
ls -a
```

Windows（PowerShell 7）:

```powershell
ls -Force
```

並記がないコードブロックは、**どの環境でも同じ**という意味です。

コマンドの下に、実行結果の例を示すこともあります。

```
On branch main
nothing to commit, working tree clean
```

このように色分けのないブロックは**実行結果**です。入力するものではありません。表示される内容は環境によって少し違うことがありますが、大まかに同じであれば問題ありません。

### ファイルの中身

```markdown:notes/todo.md
# やること

- 牛乳を買う
```

上部にファイル名の帯が付いているブロックは、**そのファイルを作って中身を書き込むもの**です。エディタで作成してください。

## 進め方のコツ

### 1. 手を動かしながら読む

Gitは、説明を読んだだけでは身につきにくいツールです。「コマンドを打つ」「結果を見る」「何が起きたか確認する」の繰り返しで少しずつ理解が深まります。

### 2. `git status` を口ぐせにする

これから何度も出てきますが、`git status` は「いま自分がどういう状態にいるか」を教えてくれるコマンドです。迷ったらとりあえず実行する、くらいの気持ちで使ってください。

### 3. わからない用語は飛ばさない

Gitには「リポジトリ」「コミット」「ステージング」といった独特の用語が出てきます。この本では初出のときに必ず説明を入れます。ぼんやりしたまま先に進むと後半でつまずくので、そのつど立ち止まってください。
