## 概要

この記事では、macOSのサポート対象外となった（なる予定の）Macで、T2 Chipを搭載したものを使う時の注意点についてまとめています。

具体的には、**ChromeOS FlexやLinux系OSを入れて延命できるのか**という観点で、できること・できないこと・作業の流れと参照先を整理しました。

結論を先に書くと、次のとおりです。

- **ChromeOS Flex は、T2チップ搭載Macには非対応です**（Google公式に「サポート対象外」と明記されています）
- **Linux は動きます**。ただし専用の対応が入ったカーネルが必要で、`t2linux` というコミュニティプロジェクトの手順に沿って作業することになります

## 背景：Intel搭載Macは、次のmacOSからサポートされません

Appleは2025年6月のWWDC25で、**macOS 26 Tahoe を Intel プロセッサ搭載Macに対応する最後のバージョン**にすると表明しました。2026年秋に登場する次のmacOSからは、Intel Macは対象外になります。

とはいえ、いきなり使えなくなるわけではありません。Appleはこの記事を書いている2026年8月時点で、macOS Tahoe・Sequoia・Sonomaの3つのバージョンにセキュリティアップデート（危険な不具合を塞ぐ修正）を出しています。

https://support.apple.com/ja-jp/100100

ただし、Tahoeへのセキュリティアップデートをいつまで続けるのか、Appleは終了時期を公表していません。

問題はその後です。セキュリティ更新が止まったOSをインターネットにつないで使い続けるのは、あまりおすすめできません。また、対応が止まるとブラウザなどのアプリも徐々に新しいバージョンが入らなくなっていきます。

ハードウェアとしてはまだ十分に動くのに、OSの都合で使えなくなる。そこで、**macOS以外のOSを入れて延命する**という選択肢が出てくるわけです。

### すでに対象外になっている機種のほうが多い

機種によって「最後に対応するmacOSのバージョン」は異なります。T2チップ搭載Macのうち、macOS Tahoeに対応しているのは次の4機種だけです。

- MacBook Pro（16インチ, 2019）
- MacBook Pro（13インチ, 2020, Thunderbolt 3ポート4基）
- iMac（Retina 5K, 27インチ, 2020）
- Mac Pro（2019）

https://support.apple.com/ja-jp/122867

つまり、これ以外のT2搭載機（2018年のMacBook Pro、Mac mini (2018)、MacBook Air の各モデル、iMac Pro など）は、**すでにTahoeより前のバージョンで対応が打ち切られています**。お手元のMacがどちらなのかは、上記のリンク先で確認してください。

## T2チップとは

**Apple T2 セキュリティチップ**は、Appleの説明では「Appleが開発した第2世代のIntel搭載モデルのMac用カスタムシリコン」とされています。2017年のiMac Proから2020年ごろまでのIntel Macに搭載されました。

「セキュリティ」と名前が付いているとおり、Appleが公式に説明しているのは主にセキュリティ機能です。起動時にOSが正規のものかを検証する「安全な起動」は、T2の役割としてAppleのサポートページに明記されています。

一方、Linux対応を進めているt2linuxプロジェクトの資料を見ると、**セキュリティ以外のかなり広い範囲もT2を経由してつながっている**ことがわかります。以下はいずれも、T2向けの専用ドライバがないと動かないものです。

- 内蔵SSD
- キーボード・トラックパッド
- カメラ
- Touch Bar
- オーディオ（スピーカー・マイク・イヤホン端子）
- Touch ID（T2の中にあるSecure Enclaveという領域が担当）

ここが今回の話のキモです。**普通のPCなら汎用の部品が担当している部分を、AppleがT2という独自チップで肩代わりしている**ため、Windows/Linux/ChromeOSといった他のOSから見ると「知らないデバイスがつながっている」状態になります。

### T2チップを搭載しているMac

以下の機種が該当します。

- MacBook Pro（2018〜2020、Intel）
- MacBook Air（2018〜2020、Intel）
- iMac（Retina 5K, 27インチ, 2020）
- iMac Pro
- Mac mini（2018）
- Mac Pro（2019）

https://support.apple.com/ja-jp/103265

### 手元のMacがT2搭載か確認する方法

Appleのサポートページに手順が載っています。

1. `option` キーを押しながらアップルメニューをクリックし、「システム情報」を選択します
2. サイドバーで「コントローラ」（macOSのバージョンによっては「iBridge」）を選びます
3. 右側に**「Apple T2チップ」**と表示されれば、T2搭載機です

:::message
Apple Silicon（M1以降）のMacには、この記事の内容は当てはまりません。Apple Silicon MacへのLinuxインストールは [Asahi Linux](https://asahilinux.org/) という別のプロジェクトの領域になります。
:::

## ChromeOS Flex：T2搭載Macは対象外です

[ChromeOS Flex](https://chromeenterprise.google/intl/ja_jp/os/chromeosflex/) は、古いPCやMacにインストールしてChromebookのように使えるようにする、Googleの無償OSです。動作が軽く、設定も簡単なので「古いMacの延命」の第一候補に挙がりやすいのですが、**T2搭載Macでは使えません**。

Google公式のヘルプの「サポートされていないハードウェア」に、こう書かれています。

> タッチバー、T2 セキュリティ チップ、M1 プロセッサを搭載した Mac デバイスはサポートされていないため、動作しても大きなバグが発生する可能性が高くなります。

https://support.google.com/chromeosflex/answer/11541806?hl=ja

実際、[認定モデル一覧](https://support.google.com/chromeosflex/answer/11513094?hl=ja) にApple製品として載っているのは6機種だけで、うち「認定済み」は Mac mini 7,1・MacBook Air 6,1・MacBook Air 7,2 の3機種です。いずれも2013〜2015年ごろの機種で、**2018年以降のT2搭載機は1台も含まれていません**。

Googleは「認定されていないデバイスに ChromeOS Flex をインストールする」というヘルプページも用意しているので、認定外の機種で試すこと自体は想定されています。ただしそこには「Google では認定モデルでのみ ChromeOS Flex の動作を保証しています」「認定されていないデバイスでは、デバイスが十分に機能している場合でも大きな問題が発生することがあります」とも書かれています。

https://support.google.com/chromeosflex/answer/11582107?hl=ja

前述のとおり、T2搭載機ではキーボード・トラックパッド・内蔵SSDがいずれもT2チップ経由でつながっており、Linuxでもこれらを動かすには専用のドライバが必要でした。ChromeOS Flexがそれに相当する対応をしているという情報は見当たりません。Google自身が「サポートされていない」と言っている以上、時間をかけて試す価値は薄いと考えてよいでしょう。

というわけで、T2搭載Macの延命は、実質的にLinux一択です。

## Linux：t2linux プロジェクトを使えば動きます

有志のコミュニティが、T2搭載Mac向けのドライバとカーネル（OSの中核部分）を整備しています。それが **t2linux** です。

https://wiki.t2linux.org/

普通のディストリビューション（Linuxの配布形態）のインストーラをそのまま使うのではなく、**T2対応のパッチが当たったカーネル入りのISOイメージ**を使う、というのがポイントです。

### 対応しているディストリビューション

wikiでガイドが用意されているのは以下です。

- Ubuntu、Linux Mint
- Debian、Pop!_OS、Zorin OS などのDebian系
- Fedora
- Arch Linux
- EndeavourOS
- NixOS
- Gentoo

Linuxに慣れていない方であれば、**Ubuntu か Linux Mint** あたりが無難です。日本語の情報も多く、見た目もWindowsやmacOSに近いので戸惑いが少ないと思います。

なお、Manjaro のガイドもありますが、wikiに「Manjaro のT2サポートは非推奨（deprecated）」と書かれているので、これから始めるなら避けたほうがよいでしょう。

### 何が動いて、何が動かないか

t2linux wikiの [Device Support and State of Features](https://wiki.t2linux.org/state/) に対応状況がまとまっています。2026年8月時点での概要は次のとおりです。

**動きます**

| 機能 | 備考 |
| --- | --- |
| 内蔵SSD | |
| 画面・内蔵GPU | |
| キーボード | |
| トラックパッド | 動きますが、macOSほどではありません（感圧タッチと手のひら誤検知の抑制がありません） |
| USB / Thunderbolt | |
| Wi-Fi | macOSのファームウェアが必要 |
| カメラ | |
| オーディオ（スピーカー・マイク・イヤホン端子） | 内蔵マイクは、DSP設定を入れないと入力音量が小さくなります（ハードウェアの特性で、ドライバ側では補正できないとのこと） |
| Touch Bar | 「Touch Barキーボード」モード。ファンクションキー、または音量・輝度などの操作キーだけが表示されます |

**部分的に動きます**

| 機能 | 状況 |
| --- | --- |
| Bluetooth | BCM4377チップ搭載機ではmacOSのファームウェアが必要。またBCM4377搭載機では、2.4GHz帯のWi-Fiにつないでいると動作が乱れるため、Wi-Fiを切るか5GHz帯を使うことが案内されています |
| スリープからの復帰 | 残っている不具合は機種によって異なります |
| 外部GPUとの切り替え | 外部GPU側の電源のオン・オフができません |
| AMD製GPU | 解像度の変更などでクラッシュすることがあります（回避策あり） |
| Mac Pro（2019） | PCIeのアドレス空間まわりで問題が報告されています |

**動きません**

| 機能 | 状況 |
| --- | --- |
| T2のSecure Enclave | macOSではTouch IDや暗号鍵の保管に使われている部分です。つまり**Touch IDは使えません** |
| T2のオーディオ／ビデオエンコーダー | macOSではSidecar（iPadをサブディスプレイにする機能）に使われている部分です |

日常使いで一番効いてくるのは **Touch IDが使えない** ことでしょうか。ログインもsudo（管理者権限での実行）も、毎回パスワード入力になります。

また、LinuxからmacOS側のAPFSパーティション（システムとデータの領域）は読めません。macOSと共有したいファイルがある場合は、別の領域を用意しておく必要があります。

## 作業の流れ

実際の手順は機種とディストリビューションによって変わるので、ここでは**流れと押さえどころ**だけ示します。詳細は必ずwikiの該当ページを参照してください。

https://wiki.t2linux.org/guides/preinstall/

### 1. バックアップを取る

これから内蔵SSDのパーティション（領域の区切り）をいじります。Time Machineなどで**必ず**バックアップを取ってください。

### 2. ディスクユーティリティでパーティションを追加する

macOSの「ディスクユーティリティ」でボリュームを選び、**「ボリュームを追加」ではなく「パーティション」ボタン**から領域を追加します。ここを間違えるとLinux側からうまく扱えません。

- Linux用に割り当てる容量は、後から変えられないものと考えて多めに確保します
- フォーマット形式はAPFS以外が推奨されています
- `/home` や `/boot` を分けたい場合は、ここで追加のパーティションも作っておきます

### 3. Wi-Fiのファームウェアを取り出す

Wi-FiとBluetoothを使うには、**Appleが提供するファームウェア（チップを動かすための小さなプログラム）をLinux側にコピーする**必要があります。この作業自体はインストール後でもできますが、macOSが起動できるうちに済ませておくほうが確実です。

wikiでは5つの方法が案内されています。

- **方法1〜3**：macOS上でスクリプトを実行してファームウェアを取り出し、Linux側で取り込む
- **方法4**：Linux側からmacOSのパーティションを読んで直接取得する
- **方法5**：Linux側からAppleのmacOSリカバリイメージをダウンロードして抽出する

つまり、macOSを消してしまった場合でも方法5で復旧できます。ただし**iMac 19,1 / iMac 19,2 / iMac Pro（iMacPro1,1）は方法4・5が使えず、方法1〜3しか選べません**。この3機種を使っている場合は、macOSが動くうちに必ず取り出しておいてください。

なお方法4・5はLinux上で作業するため、Wi-Fiが使えない状態でインターネットに接続する手段（有線LAN、スマートフォンのUSBテザリング、外付けWi-Fiアダプタなど）が別途必要になります。この点でも、先に済ませておくほうが楽です。

https://wiki.t2linux.org/guides/wifi-bluetooth/

### 4. インストール用USBメモリを作る

各ディストリビューションの**T2対応ISO**をダウンロードし、balenaEtcherやUSBImagerなどでUSBメモリに書き込みます。通常版のISOではありません。

### 5. 起動セキュリティユーティリティの設定を変更する

ここがT2搭載Mac特有の作業です。初期状態では、Apple以外のOSは起動すらできません。

1. Macの電源を入れ、Appleロゴが出たらすぐ `command` + `R` を押し続け、macOS復旧（リカバリ）を起動します
2. ユーザの選択画面が出たら、パスワードのわかるユーザを選んで管理者パスワードを入力します
3. 「macOSユーティリティ」ウインドウが出たら、メニューバーの「ユーティリティ」→「起動セキュリティユーティリティ」を選びます
4. 認証を求められたら「macOSのパスワードを入力」をクリックし、管理者アカウントのパスワードを入力します
5. **「安全な起動」**を **「セキュリティなし」** に変更します（初期値は「完全なセキュリティ」です）
6. **「許可する起動メディア」**を、外部メディアやリムーバブルメディアからの起動を許可する設定に変更します（初期値は「許可しない」です）

https://support.apple.com/ja-jp/102522

### 6. USBメモリから起動してインストールする

`option` キーを押しながら電源を入れると起動ディスクの選択画面が出ます。オレンジ色のアイコンで表示される「EFI Boot」を選ぶと、Linuxのインストーラが立ち上がります。

あとは通常のLinuxインストールとほぼ同じです。パーティションの選択のところだけ、手順2で作った領域を指定するよう注意してください。

### 7. インストール後にセキュリティ設定を戻す

内蔵SSDにインストールしたのであれば、「許可する起動メディア」は再び「許可しない」に戻せます。

また、「安全な起動」を無効にしたぶんの穴埋めとして、起動セキュリティユーティリティで**ファームウェアパスワード**を設定しておくと安心です。これは、指定した起動ディスク以外から勝手に起動されるのを防ぐ機能です。

## 注意点まとめ

改めて、作業前に知っておいたほうがよいことを整理します。

### macOSは消さずに残す

繰り返しになりますが、これが一番大事です。

- Wi-Fi/Bluetoothのファームウェアを取り出す作業が一番簡単に済む（機種によってはmacOSが必須）
- トラブルが起きたときに戻れる場所がある

t2linux wikiでも、バックアップとして、また今後のファームウェアアップデートを受け取るために、macOSは残しておくことが推奨されています。

### セキュリティレベルは下がります

「安全な起動」を「セキュリティなし」にするということは、起動ディスクに対する検証を一切行わなくなるということです。個人利用であれば過度に心配する必要はありませんが、業務で使う端末であれば、組織のルールに反しないか確認してください。ファームウェアパスワードの設定はしておきましょう。

### スピーカーの音量に注意

t2linux wikiによると、**Appleによるスピーカーのチューニングはすべて macOS 側で行われており**、Linux用に同等の設定が用意されているのは、現状 MacBook Pro 16インチ 2019 だけとのことです。

そのDSP設定には、次の注意書きが添えられています。

> 機種ごとに専用の設定が必要です。他の機種に使わないでください。スピーカーを損傷するおそれがあります。また、macOSと同じ音質は期待しないでください。

自分の機種向けのもの以外は使わないでください。

https://wiki.t2linux.org/guides/audio-config/

### 起動しなくなったときの復旧手段

作業に失敗してMacが起動しなくなった場合、**もう1台のMac**をつないで、DFU（デバイスファームウェアアップデート）モードからファームウェアを立て直せます。T2搭載Macは、Appleシリコン搭載Macと並んでこの操作の対象になっています。

操作には「復活」と「復元」の2つがあり、**結果が大きく違います**。

| | 内容 | データ |
| --- | --- | --- |
| **復活（revive）** | ファームウェアとrecoveryOSを更新する | **消えません** |
| **復元（restore）** | 消去して工場出荷時の設定に戻す | **消えます** |

Appleも「まずは、復活を試してください。復元よりも時間がかからず、Macは消去されません」と案内しています。いきなり復元を選ばないでください。

必要なものは次のとおりです。

- **macOS 14以降が動く別のMac**（インターネット接続と32GB程度の空き容量が必要）
- **データ転送と充電に対応したUSB-C - USB-Cケーブル**（**Thunderbolt 3ケーブルは使えません**）

なお、以前はApple Configurator 2を使う手順でしたが、現在はホスト側のFinderに表示される「DFUウインドウ」から操作します。

また、T2搭載Macで「復元」を行った場合は、そのあとmacOS復旧から自分でmacOSをインストールし直す必要があります。

https://support.apple.com/ja-jp/108900

もう1台Macを用意できるかどうかは、作業前に考えておいたほうがよいポイントです。

### 売却・下取り・修理に出す予定があるなら

Linuxが入ったままだと、下取りの査定や修理受付で断られる、あるいは説明に手間がかかることがあります。手放す予定があるなら、あらかじめmacOSに戻せる状態にしておきましょう。

### サポートは自己責任です

t2linuxは有志によるコミュニティプロジェクトです。Appleのサポートも、ディストリビューションの公式サポートも受けられません。うまくいかないときは自分で調べる、あるいはコミュニティ（DiscordやMatrix）で聞く、というスタンスが必要です。

## そのほかの選択肢

### OpenCore Legacy Patcher

「他のOSではなく、あくまでmacOSを使い続けたい」という場合は、**OpenCore Legacy Patcher** というプロジェクトがあります。「Experience macOS just like before」を掲げ、サポート対象外になったMacで新しいmacOSを動かすためのツールです。

https://dortania.github.io/OpenCore-Legacy-Patcher/

ただし、自分のMacが対象になるか、また今後のmacOSに対応し続けるかは、公式サイトの対応機種一覧と告知を都度確認してください。この記事では確認していません。

### Windows

Boot Campを使ってWindowsを入れる方法もあります。ただし、Appleが用意しているのは「Boot Camp アシスタントで Mac に Windows 10 をインストールする」という案内で、**Windows 11 向けの手順は公開されていません**。

https://support.apple.com/ja-jp/102622

そしてそのWindows 10は、Microsoftのライフサイクル情報のとおり**2025年10月14日にサポートが終了しています**。

https://learn.microsoft.com/ja-jp/lifecycle/products/windows-10-home-and-pro

延命目的としては、あまり筋のよい選択肢とは言えません。

## おわりに

まとめると、こうなります。

- ChromeOS Flexは、T2搭載Macでは**使えません**
- Linuxは**使えます**が、t2linuxの手順に沿った準備が必要です
- Touch IDは諦めることになります
- macOSのパーティションは残しておきましょう

Intel Macは、まだ数年はmacOSのまま使えます。慌てて移行する必要はありませんが、「使えなくなったら捨てるしかない」わけではない、ということは知っておいて損はないと思います。

手元の機械をできるだけ長く使うのは、財布にもやさしく、環境にもやさしい選択です。役目を終えたと判断したときの処分方法については、以下の記事もあわせてご覧ください。

https://zenn.dev/kwaka1208/articles/how-to-dispose-devices
