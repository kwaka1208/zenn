## はじめに

エンジニアを目指して学ぶ人のための教材「ルーキーエンジニアのためのクエスト」を作りました。GitHub のアカウントがあれば、誰でも無料で試せます。

https://github.com/kwaka1208/quests-hq-beta

この記事では、このクエストを作った理由と、どんなものなのかを紹介します。

## なぜ作ったのか

エンジニアを目指して学ぶ人は、ここ数年でずいぶん増えました。スクールや独学の教材も充実しています。

ただ、そこで学ぶのは、多くの場合プログラミング言語やフレームワークといった「技術」です。

実際にエンジニアとして働くには、技術のほかにも必要なスキルや、仕事の進め方があります。たとえば次のようなことです。

- README（ソフトウェアの説明書）を読んで、手順どおりに動かす
- エラーメッセージを読んで、何が起きているかをつかむ
- うまくいかないとき、状況を整理して人に報告する
- 自分が変更した内容を、プルリクエスト（変更の提案）で説明する

開発の現場では、こうした文書を毎日読み、毎日書いています。ところが、ドキュメントを読んだり書いたりするのが苦手な人はとても多いです。エラーの報告も同じで、「動きません」の一言だけが届いてしまう、ということがよくあります。

そこで、これを RPG（ロールプレイングゲーム）のように、楽しく体験できるものにしました。それがこのクエストです。

もうひとつの特徴は、すべて Git と GitHub で進めることです。クエストを進めるうちに、fork（リポジトリを自分用にコピーすること）、コミット、Issue、プルリクエストといった操作に自然と慣れていきます。Git の練習にもなります。

## こんな方に使ってほしい

このクエストは、次のような方に使っていただくことを考えて作りました。

- **企業研修の担当の方**：新入社員や、エンジニアに職種を変える社員の研修で、技術の研修とあわせて、文書の読み書きや GitHub での仕事の進め方を体験してもらえます
- **情報系の学校（大学、専門学校）の先生**：授業で使うことを想定して作っています。読むクエストと書くクエストを組み合わせて、授業の流れに合わせて進められます
- **独学している方**：GitHub のアカウントがあれば、1人でも自分のペースで進められます

## どんなクエストなのか

あなたは、架空の小さなソフトウェア会社「Northwind」の新入社員です。先輩に案内されながら、会社の仕事を「クエスト」として1つずつ片づけていきます。

クエストには2つの種類があります。

- **読むクエスト**：README、エラーメッセージ、`--help` の表示、Issue などの文書を読み解いて、答えを探す謎解きです
- **書くクエスト**：会社の仕事として、エラーメッセージやバグの報告、プルリクエストの説明などを書きます。読む人に伝わる文になっているかを、チェックのプログラムが確かめます

クエストは Quest 0 から Quest 24 まであります。最初の Quest 0「The First Day」は、初出社の朝に、README を読まないとオフィスの Wi-Fi が使えない、という場面から始まります。

題材の文書は英語です。開発の現場で読み書きする文書の多くが英語だからです。ただし英語の授業ではないので、長い文を全部訳す必要はありません。見出しを手がかりに必要なところを探して読み、伝わるように短く書く練習をします。物語や進め方の説明は日本語で書いてあります。

作業はすべて GitHub Codespaces（ブラウザの中で動く開発環境）で行うので、自分のパソコンに何かをインストールする必要はありません。

すべてのステージに答えると、`FLAG{...}` の形の「フラグ」がもらえます。フラグがクエストを終えたしるしです。順位や点数はなく、ほかの人と競うものではありません。自分のペースで進められます。

## 2つのリポジトリ

クエストでは、GitHub の2つのリポジトリを使います。

- **本部**：クエストの受付と、進み具合の記録の場所です。参加登録と、フラグの提出をします

https://github.com/kwaka1208/quests-hq-beta

- **現場**：クエストを実際に体験する場所です。fork して、自分の Codespaces でクエストを解きます

https://github.com/kwaka1208/quests-beta

始め方や遊び方の詳しい手順は、それぞれのリポジトリの README に書いてあります。まずは本部の README から読んでみてください。

## 試す前に知っておいてほしいこと

### クエストは、すべて公開済みです

現場の README には「新しいクエストを受け取る」という手順があります。これは授業で1回ずつクエストを配ることを想定して書いたものです。

このパブリックベータでは、Quest 0 から Quest 24 まで、すべてのクエストがすでに公開されています。fork した時点で全部そろっているので、都度受け取る必要はありません。好きなクエストから始められます。

### フラグを提出すると、記録が公開されます

フラグの提出は、本部のリポジトリに Issue を立てて行います。本部は公開リポジトリなので、提出したフラグと、どのクエストをクリアしたかの記録は、誰でも見られる状態になります。

それが嫌な方は、フラグを提出しなくてもかまいません。フラグは手元のプログラムで表示されるので、提出しなくてもクエストは最後まで進められます。

なお、本部・現場とも公開されているので、Issue やプルリクエストに本名や学校・会社の名前は書かないでください。

### 開発途上のパブリックベータです

このクエストは、まだ開発の途中です。現時点ではパブリックベータという位置付けで、クエストの内容や進め方、リポジトリの構成などは、今後変わる可能性があります。

もともと授業で使うことを想定して作っているため、README には「授業」や「先生」「班」という言葉が出てきます。仲間とプルリクエストをレビューし合うクエストなど、1人では進めにくいものもあります。

## おわりに

技術を学んでいる人が、現場で読み書きする文書に少しでも早く慣れて、「README を読んでみよう」「エラーをきちんと報告しよう」と思えるようになったら嬉しいです。

わかりにくいところや、うまく動かないところを見つけたら、現場のリポジトリに Issue で知らせてください。それも、立派なオープンソースへの貢献です。
